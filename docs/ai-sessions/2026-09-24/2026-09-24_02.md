1. **The first `inventory` is the root package.** It's the application itself: your reverse domain (`com.robertwoolbright`) plus the project name. `InventoryApplication.kt` sits there, and so does `@SpringBootApplication`. It does look like a stutter. If an interviewer asks, the short answer is: "the root package is the app, and the subpackage is the feature, which here happens to share the app's name." **1. `var quantity` should be `val quantity`.**
- `var` gives the property a setter, so any code holding an `InventoryItem` can do `item.quantity = 999`. The checklist asks for read-only properties.
- **Why it matters here:** in this design the database owns the stock count, and every change goes through one atomic SQL statement. That's the oversell protection. An `InventoryItem` is a snapshot of one row at the moment it was read. If it can be changed, someone might later write "read the item, subtract, save it back". That read-then-write pattern is exactly the race the TODO's negative-control test is meant to catch.
