### Claude

It compiles and the KDoc check passes. The logic is right: the repository call, then Elvis, then the throw, the same shape as `getInventory`. I have two things for you to change and one optional one.

**1. `@Throws` should be `@throws` (line 27).** KDoc tags are case-sensitive and lowercase. `@Throws` with a capital T is a different thing: it's Kotlin's `kotlin.jvm.Throws` annotation, which puts a Java-style checked-exception declaration on the method. In a doc comment, documentation tools like Dokka and the IDE won't treat it as a tag, so the "throws" line won't show up where it should. The KDoc check only confirms a doc comment exists, not its tags, which is why it passed. You had this same mix-up in session 3, so it's worth remembering: **lowercase in KDoc, capitalized as an annotation**.

**2. Rename `addStock` to `receiveInventory` (line 29).** Tests will pass either way because they reach the service through HTTP, so this is about naming. There are two reasons:
- **Each layer names things in its own terms.** The repository speaks the database's language: `findAll`, `findBySkuId`, `addStock`. The service speaks the business's language, and "receiving inventory" is the business action from the brief. Your service already does this: `listInventory` and `getInventory`, not `findAll` and `findBySkuId`.
- **Two functions called `addStock`** in different layers makes stack traces and "find usages" confusing, because you can't tell at a glance which one you're looking at.

**3. Optional: reword the KDoc.** "Returns the updated row after adding or updating the item" mentions a *row*, which is the database's view again, and "adding or updating" is a bit circular. Something like "Adds `quantity` to the SKU's stock, creating the SKU if it's new, and returns the new total" says what a caller would want to know. Use your own words.
