### Claude

Step 7 is the controller's `@PostMapping`. It's the thinnest layer: take the HTTP request, hand it to the service, and return what the service gives back.

**Where:** [InventoryController.kt](src/main/kotlin/com/robertwoolbright/inventory/inventory/InventoryController.kt), as a third function under `getInventory`.

### What the function needs

1. **The mapping.** `@PostMapping("/{skuId}")`. The class's `@RequestMapping("/inventory")` already supplies the prefix, the same way it does for your `@GetMapping("/{skuId}")`.
2. **Two parameters, from two parts of the request:**
   - The SKU comes from the URL, with `@PathVariable`, exactly as in `getInventory`.
   - The quantity comes from the JSON body. `@RequestBody` tells Spring to have Jackson turn the body into your `InventoryQuantity` data class.
3. **`@Valid` on the body parameter.** This is the one that's easy to miss. Your `@Min(1)` on `InventoryQuantity` is only a label, and nothing checks it unless the parameter is marked `@Valid`. Without it, `{"quantity": 0}` would reach the service and get added to the stock. The import is `jakarta.validation.Valid`.
4. **The body.** Call `inventoryService.receiveInventory(...)`. Remember that you chose String + Int for the service, so the controller unwraps the DTO: pass the SKU and the body's `quantity` property, not the whole object.
5. **The return type is `InventoryItem`.** Spring returns 200 with JSON by default, which is what the contract wants. It wants 200, not 201, so you don't need `@ResponseStatus`.

### A parallel example in a different domain

For a library that adds copies of a book:

```kotlin
@PostMapping("/{isbn}")
fun addCopies(@PathVariable isbn: String, @Valid @RequestBody request: CopyCount): Book =
    bookService.addCopies(isbn, request.count)
```

Here's how it maps onto yours: `isbn` → `skuId`, `CopyCount` → `InventoryQuantity`, `request.count` → the body's `quantity`, `Book` → `InventoryItem`, `bookService.addCopies` → `inventoryService.receiveInventory`. Pick your own name for the function. `getInventory` handles the GET, so the POST needs a verb that says what it does.
