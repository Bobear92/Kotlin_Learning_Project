### Claude

Yes, you need a name for it. The reason is the `Purchased` branch: `when (inventoryRepository.removeStock(skuId, quantity)) { ... }` would compile, but inside that branch you'd have nothing to call `.item` on. The two `data object` branches only throw, so they don't need a name. `Purchased` does, because you read the item out of it.

There are two ways to name it:

1. **A separate `val` above the `when`.** Something like `val result = ...removeStock(...)`, then `when (result) { ... }`. This is what you'd write in Java.
2. **Declare the `val` inside the `when` parentheses.** Kotlin lets you write `when (val result = <expression>) { ... }`. `result` then exists only inside the `when`, and the function doesn't gain a variable that's used once. This is the idiomatic Kotlin version.

Both give you the smart cast. Once `is PurchaseResult.Purchased` matches, the compiler knows `result` is a `Purchased` inside that branch. That works because `result` is a local `val` and can't change between the check and its use.

Here's the same idea in a different domain, a library checkout, so you can see how it's shaped:

    LoanOutcome.AllCopiesOut -> throw NoCopiesAvailableException(bookId)

This example also answers my first question from before. The `data object` branches don't use `is`: there's only one instance of each, so the branch names that object directly. The answer is in how `Purchased` is declared. Here's the line from [PurchaseResult.kt](src/main/kotlin/com/robertwoolbright/inventory/inventory/PurchaseResult.kt):

```kotlin
data class Purchased(val item: InventoryItem) : PurchaseResult
```

Split that into two parts:
- **`Purchased`** is the name of the **type**, like a class name.
- **`item`** is the one **property** each `Purchased` carries: the `InventoryItem` with the remaining stock.

A `Purchased` works like a box: `Purchased` is the kind of box, and `item` is what's inside it. The `is PurchaseResult.Purchased ->` line asks "is this that kind of box?" Once the answer is yes, you want the contents, which is `purchaseOutcome.item`.

`purchaseOutcome.Purchased` asks the box for a property named `Purchased`, and there isn't one. That's why the compiler says "Unresolved reference 'Purchased'".

The same thing in Java terms:

```java
if (pet instanceof Dog dog) {
    return dog.getName();   // not dog.Dog
}
```

You check the type (`Dog`), then read the field (`name`). The Kotlin version is `is PurchaseResult.Purchased -> purchaseOutcome.item`.

This is also what the smart cast does for you. Outside the branch, `purchaseOutcome` has type `PurchaseResult`, and `PurchaseResult` has no `item` property, so `purchaseOutcome.item` wouldn't compile there. Inside the `is Purchased` branch, the compiler knows it's a `Purchased`, so `.item` becomes available. Java makes you name a new variable (`Dog dog`) to get that. Kotlin reuses the same name.
