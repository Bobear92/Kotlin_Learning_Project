## What you're building

**File:** `src/main/kotlin/com/robertwoolbright/inventory/inventory/error/InventoryExceptionHandler.kt` (new file, next to `SkuNotFoundException.kt`)

**The concept:** Your service throws `SkuNotFoundException`, and nothing catches it. It travels up through your controller into Spring. Spring doesn't know what it means, so it becomes a 500 error (in MockMvc you see it as that `ServletException`). A **controller advice** is a class Spring checks whenever *any* controller throws. If one of its methods says "I handle this exception type", Spring calls that method and sends back whatever it returns instead of the error.

Java comparison: it's a global `try/catch` around every controller method. You write it once and Spring wires it in.

**The pieces to look up:**

1. **`@RestControllerAdvice`** on the class. It marks the class as an advice and makes return values go straight into the response body, the same way `@RestController` does.
2. **`@ExceptionHandler(SkuNotFoundException::class)`** on the function. `::class` is Kotlin's version of Java's `SkuNotFoundException.class`.
3. **The function takes the exception as its parameter.** Spring passes in the one that was thrown.
4. **It returns `ResponseEntity<String>`**, because you need to control three things: the status, the content type and the body. Look at `ResponseEntity.status(...)`, which chains into `.contentType(...)` and then `.body(...)`. The values you need are `HttpStatus.NOT_FOUND` and `MediaType.TEXT_PLAIN`.

**One Kotlin question to decide:** the body should be the exception's message, which is already `"SKU not found: $skuId"`. But `Throwable.message` is typed `String?` (nullable) in Kotlin, because Java's `getMessage()` can return null. You have three ways to get a plain `String`:

- `ex.message ?: ""` uses the Elvis operator ("if null, use this instead")
- `ex.message!!` means "I promise it's not null" and throws if you're wrong
- change `SkuNotFoundException` to keep `skuId` as a property and build the text in the handler

Pick one and be ready to say why. It's a good interview question. (Hint: can your constructor ever produce a null message?)

### Claude

`ResponseEntity` is Spring's object for a whole HTTP response: status, headers and body together. When a controller returns a plain `InventoryItem`, Spring fills in 200 and JSON for you. When you return a `ResponseEntity`, you set each part yourself.

## It's a builder

You don't call a constructor. You start with a static method and chain calls onto it. Each call returns a builder object, not the finished response, and the last call produces the `ResponseEntity`:

| Call | Takes | Returns |
|---|---|---|
| `ResponseEntity.status(...)` | an `HttpStatus` (or an `Int` like `404`) | a `BodyBuilder` |
| `.contentType(...)` | a `MediaType` | the same `BodyBuilder`, so you can keep chaining |
| `.body(...)` | the body object | the finished `ResponseEntity<T>` |

The type of what you pass to `.body(...)` becomes the `T`. Passing a `String` gives you `ResponseEntity<String>`, which is what your function returns.

It's the same idea as Java's `StringBuilder().append(a).append(b).toString()`: each step returns something you can call the next step on.

## Parallel example (different domain)

A library app where borrowing a book that's already on loan returns 409 Conflict as plain text:

```kotlin
@ExceptionHandler(BookOnLoanException::class)
fun handleBookOnLoan(ex: BookOnLoanException): ResponseEntity<String> =
    ResponseEntity.status(HttpStatus.CONFLICT)
        .contentType(MediaType.TEXT_PLAIN)
        .body(ex.message ?: "")
```

How it maps to your code:
- `BookOnLoanException` here = your `SkuNotFoundException`
- `HttpStatus.CONFLICT` here = the 404 constant you need
- `handleBookOnLoan` here = your own function name
- `ex.message ?: ""` is one of the three null options from my last message. Choose your own; you don't have to copy this one.

Kotlin notes:
- `= ...` after the signature is the expression-body style you already used in the controller.
- The dots at the start of each line are fine in Kotlin. A line that starts with `.` continues the one above it.

## A trap to avoid

`ResponseEntity.notFound()` looks like a shortcut, but it returns a `HeadersBuilder`, and that has no `.body(...)` method, only `.build()`. So you'd get a 404 with an empty body and the tests would fail on the body text. Use `status(...)` so you can set a body.

Imports you'll need: `org.springframework.http.ResponseEntity`, `org.springframework.http.HttpStatus`, `org.springframework.http.MediaType`, plus the two annotations from `org.springframework.web.bind.annotation`.
