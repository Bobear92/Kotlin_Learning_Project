**The Kotlin concept:** in Java you'd write a constructor that calls `super(message)`. In Kotlin, the superclass call goes in the class header, right after the colon, so the whole class often fits on one line. Here's the same shape in a different domain:

```kotlin
/** Thrown when a book lookup finds no row; mapped to 404 by the web layer. */
class BookNotFoundException(isbn: String) : RuntimeException("Book not found: $isbn")
```

Things to notice:
- `isbn: String` has no `val`, so it's just a constructor parameter, not a stored property. Add `val` only if something later needs to read `exception.isbn`. The handler can use `ex.message`, so it doesn't.
- `: RuntimeException(...)` both extends the class and calls its constructor.
- `"...$isbn"` is a string template, like `"Book not found: " + isbn` in Java.
- Kotlin has no checked exceptions, so there's no `throws` clause anywhere. Extending `RuntimeException` is still the convention, and it's what Spring expects.

**Contract detail:** the controller tests expect exactly `SKU not found: missing`, so match that text character for character.
