Step 4 is the controller. You'll add one function to [InventoryController.kt](src/main/kotlin/com/robertwoolbright/inventory/inventory/InventoryController.kt), next to `listInventory`.

## What it needs to do

`GET /inventory/CW-XYCS-BM-01` should call `inventoryService.getInventory("CW-XYCS-BM-01")` and return the `InventoryItem`. Spring turns that into JSON, just as it does for `listInventory`.

**The controller doesn't handle the 404.** If the SKU is missing, the service throws `SkuNotFoundException` and the controller lets it pass through. Step 5's `@RestControllerAdvice` catches it and turns it into the 404. That keeps the controller to one line.

## Two new pieces

1. **`@GetMapping("/{skuId}")`**: the path is added to the class's `@RequestMapping("/inventory")`, so the full path is `/inventory/{skuId}`. The braces mark a *path variable*, a slot in the URL that gets filled in.
2. **`@PathVariable`** on a function parameter: it tells Spring to copy the value in that slot into this parameter. If the parameter name matches the name in the braces exactly, you don't have to repeat it. In Java you'd often write `@PathVariable("skuId") String skuId`. In Kotlin the compiler keeps parameter names, so the plain annotation is enough.

## Example in a different domain

A library app with books looked up by ISBN (`isbn` here = your `skuId`, `Book` = your `InventoryItem`, `bookService.getBook` = your `inventoryService.getInventory`):

```kotlin
// Contract: paths./books/{isbn}.get — 200 application/json Book; 404 text/plain when missing.

/** Returns the book with the given ISBN for GET /books/{isbn}. */
@GetMapping("/{isbn}")
fun getBook(@PathVariable isbn: String): Book = bookService.getBook(isbn)
```

Note that the annotation sits inside the parameter list, directly before the parameter it applies to.
